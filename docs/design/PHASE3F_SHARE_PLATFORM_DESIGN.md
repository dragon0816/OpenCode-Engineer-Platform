### 2.3 版本、資產型態與發佈

`AssetIdentity` 是 `namespace/name@version`，版本須完整 SemVer。`PublishedAssetPackage` 包含 `kind,metadata,description?`，只有已發布且有 `package:{artifact_ref,sha256}` 的資料可分發。metadata 有 owner、visibility、分類、依賴、相容性、來源與審核／權限等。平台另以名稱維護持有者、共同編輯者及存取規則，並以版本記錄棄用。棄用版不能新選取。SemVer 依數字與 prerelease 排序，build metadata 不改變優先順序。 [識別與 metadata](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/common/assets.py#L72-L91) · [資產欄位](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/common/assets.py#L171-L200) · [目錄契約](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/common/distribution.py#L24-L60) · [版本](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/common/ownership.py#L30-L87) · [存取及棄用路由](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/control_plane/member_http.py#L423-L454)

### 3.1 連線、信任與帳號

- 「設定 → 能力與 Share Platform」保存 `Member Portal URL` 與進階 `Bridge API URL`、各連線／信任狀態、最後成功時間及更新頻率。兩個 URL 從擁有者提供的部署資料設定，介面不猜另一個 port。URL 限 HTTPS origin，可明確設公司管理的私網位址，拒絕 userinfo、query、fragment、跨 origin 轉址與環境代理。遠端請求由 Windows 本機 Adapter 組裝固定路由，瀏覽器、助理工具和外掛無通用代理入口。只設 Portal 可登入、送審及使用該介面已支援的功能。Bridge 相關操作顯示待設定。 [AEP listener 分離](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/control_plane/app.py#L247-L275)

### 3.3 通用安裝、更新與回復

1. 目錄讀取預設採 Member catalog。在已登錄且需取得核准的 BI dataset 等額外類型時併用 Bridge catalog。來源鍵固定為本機平台設定 ID、帳號／Bridge 綁定、kind 與 exact identity。不以名稱覆蓋本機項目。同名但來源不同的套件需由使用者選擇。`assets/manifest` 只供預覽，顯示 413 或 null 時可用目錄摘要，不從重新序列化的 JSON 驗原 artifact。
2. 擁有者確認要下載的精確版本。重新檢查 entitlement 與可見版本後 `select`（更新優先用 `replace`）。再 `/v1/sync`，只回報該綁定下已驗證實際存在的 Marketplace identity，排除本機獨立套件。禁止跟隨 `artifact_ref` 發 HTTP。串流限制回應與 staging 空間，核對 `authorization` 的裝置、成員、active selection、plan actor、plan bridge、因本次操作允許的 identity、單一 artifact 對應及同一版本的目錄雜湊。AEP 的 sync 可送其他選取，OEP 用專用單成員裝置，驗整個 envelope，只匯入有本機確認的項目，其他內容不寫入磁碟。意外的成員綁定或不一致權限須中止並重新對帳。BI 直接下載改核對會員 entitlement、回應 identity、宣告長度與 digest。 [AEP 同步範圍](https://github.com/dragon0816/agentic-engineering-platform/blob/861d0c0ca0813073f3944d4aff88818980beff2a/src/control_plane/service.py#L194-L244)
3. 解碼後先驗平台提供的原 bytes SHA-256，再驗 manifest、身分、依賴、內容權限及格式對應。ZIP 或多檔包逐件驗雜湊／長度及數量、解壓比例、總大小。拒絕越界路徑、UNC／ADS、Windows 保留名、重複／大小寫碰撞、link／reparse point、裝置路徑和 JSON 重複鍵，且產物不可覆寫既有受管資料。使用同磁碟私有暫存及經驗證的 handle，產物路徑由本機 ID 產生。TLS 身分加服務端摘要提供來源與傳輸完整性，審核、相容性和本機授權仍各自驗證。轉換版保存來源 SHA-256、轉換器版本與本機成品 SHA-256。 [既有檔案邊界](PHASE3B_MULTI_AGENT_DESIGN.md#32-工具呼叫歸屬與檔案安全)
4. 用每個來源族的序列化操作日誌記選取、下載、驗證、同磁碟原子移動和清冊寫入。只在本機安裝器 durable receipt 完成後標已安裝。關聯不同資料庫時以安裝器收據對帳，一次只切換該類型自己的有效指標。重試同身分同雜湊回既有收據，原版本同身分但雜湊變更即隔離並提示，重啟回收無收據 staging。遠端選取成功、本機失敗時顯示「已選取，安裝未完成」，允許重試或由擁有者撤回。本機舊版資料與授權不被失敗的下載覆寫。`duplicate_selection`、`selection_missing` 或斷線後寫入結果不明，用 catalog／選取與本機 journal 對帳，避免重複送出。
5. 目錄更新以 entitlement 和完整 SemVer 判斷較新相容版，固定比較同來源同名同類，忽略棄用與不相容版，預設穩定版、手動下載切換。建議預設只手動重新整理，可選每天於 OEP 開啟時檢查 metadata，採退避與上次有效快取。顯示權限／依賴差異，新增權限、可執行 bytes 或內容範圍變化需再確認。每次執行固定當前版本／hash，切換在安全邊界生效。回退只選仍符合平台政策、且本機驗證通過的版本。需要時明示並確認遠端 `replace`。平台棄用與存取撤銷各顯示原因，當完整成功的目錄顯示既有已安裝版缺席時，先用精確版本詳情或可用的 entitlement status 查原因。確認存取或裝置被撤銷時停用該來源執行／查詢，保留檔案與稽核供擁有者處理。移除本機與解除平台選取為兩個有明示效果的動作。

### 3.5 提交、離線與稽核

- 擁有者從已核准的 3E Skill／Workflow 草稿或已安裝的自有版選「提交審核」。Adapter 產生可表達相同語意的 AEP manifest，檢查版本、格式、依賴、讀者、分級、再散布權及秘密，預覽實際會送的檔案／資料和權限。需要平台沒有的能力或欄位時保留草稿並說明缺項。OEP 的合成試跑與本機核准接在 3E／R11 流程，遠端由平台審核。note 限用途與版本說明，預設最小讀者範圍。逐次由擁有者確認才送往可信的 Portal origin。
- 在本機 journal 以來源版本、匯出雜湊、受眾及操作 ID 鎖定待送內容。回執保存服務端 ID、分配版號與狀態。網路在 POST 後中斷時顯示「送出結果未確認」，以 `assets/submissions`、既有清單基準、提交時間、提交者／名稱、變更及稿件 metadata 對帳。服務未提供 idempotency key 或回傳客戶端雜湊，無法確定唯一匹配時需擁有者查 Portal，再決定是否重送。只允許撤回自己的待審。核准後可在目錄查到同一精確版本。退回可複製成新草稿。Portal 保留審核及發布權。
- 知識由擁有者在 3G 完成本機 review／publish，再匯出指定 revision。只有可無損且經政策核准的 BI 快照才接 `bi-datasets/publish`，沿用首版送審與後續版本發布語意，提交前顯示差異。基底過期時重新讀 status 和確認。一般知識 `.oepkb`、MCP binary、OEP Plugin 需平台正式契約，先提供本機匯出／匯入並顯示平台上架未可用。未以其他資產種類冒充或塞入自訂欄位。已發布知識保留 Plugin／版本的 provenance，即使讀端未安裝建置工具也能引用。
- 離線保留當前綁定的最小 catalog metadata，顯示最後成功時間與可能過時。顯式登出／換帳號清快取。已驗證本機套件在沒有已知撤銷、符合最新已知分級及平台政策時，依原 OEP grants 繼續使用。離線可走明確的本機選檔安裝，不補送選取、提交或同步。恢復連線先讀 catalog／回執再由擁有者操作。若公司要求定期驗權，需確認使用租期與起算條件。
- 稽核在本機保存固定事件與結果碼、時間、操作 ID、origin 設定 ID、帳號／裝置 opaque ID、資產身分／版本和 digest、權限變更、平台提交／核准狀態。區分網路錯誤、認證過期、無權、格式不支援、同版雜湊相異及 staging 失敗，訊息由在地化允許清單映射。錯誤 body／URL／header 先分類後丟棄。稽核不含 package 描述、manifest、憑證、個人帳號名稱、輸入內容或 response 原文。操作紀錄採既有本機資料維護流程與留存政策，對外匯出只取去識別事件、狀態及耗時。

## 5. 驗收設計

### 5.1 Windows 跨機驗收

在擁有者的公司筆電或目前這台已核准機器，以隔離 OEP profile／資料目錄連到擁有者的測試機上的 Shared Capability Marketplace。由平台管理者準備專用最小權限成員、另一個審核身分、核准的專用 Bridge、測試 namespace／最小讀者範圍和合成套件（兩版 Skill、受控 Workflow、一份可引用知識，MCP／Plugin 在正式契約啟用後加入）。只使用這組測試資料。實機帳號、憑證、URL、活動紀錄及原內容由擁有者在受管位置處理。測試結果只留類型、版本流程、狀態碼、回應形狀、耗時、範圍及是否通過。

| 序列 | 驗收證據 |
| --- | --- |
| 信任、登入、綁定 | 未 pin／錯 pin 時服務收不到帳密。核對 pin 後兩個 health 成功。`me`／`probe` 確認帳號和裝置一致，重啟可用受保護 login 換 session。測次數受控的錯帳號、過期、撤銷、換 pin 及離線，UI 正確區分。 |
| 瀏覽與本機安裝 | Browse 僅見可用合成項，依分類、搜尋及已選取篩選。核對兩版 SemVer、選取後 sync 的 identity／digest，重做得到既有收據。授權給第 1 位助理並驗證其可用 Skill／Workflow，確認第 2 位助理被拒絕。知識同樣檢查有／無 grant，成功回到可查核引用，讀端不需建庫 Plugin。 |
| 斷線、更新及回復 | 選取後模擬斷線，連回先對帳再繼續。測更新時舊版仍可辨識、逐版本確認、回退、棄用與本機移除。撤銷用測試裝置／測試成員，核對活動無影響其他裝置與資產。 |
| 提交與審核 | 用合成 Skill／Workflow 送件，成員看到待審，未核准版不可安裝。審核者於 Portal 核准一件、退回一件。成員在 OEP 查版號及回執，另測自己的待審件撤回。若核准 BI 契約，再驗首版待審／核准及後續發布。跨機確認 MCP／Plugin 時只跑無副作用的測試件。 |
| 結束 | 撤銷測試 login／Bridge、解除選取，請平台管理者依測試 namespace 政策撤回、棄用或清理合成資料，移除隔離 profile。下載的測試 bytes、已送 manifest 及憑證不得進入 repo 或 CI。 |

本設計階段實機只驗 §1 的未登入路由。以上皆是後續驗收，認證與權限操作 **requires login — to verify with the owner's test account**。

### 5.2 CI 合成 Marketplace stub

- 在 loopback 跑兩個獨立 HTTPS listener，用每次測試生成的憑證、不需模型的合成測試資料、假 login／session／Bridge token 與可控時鐘。重現 §2 的 HTTP method、回應、版本、權限與字節分隔，雜湊從合成 package 重算。另用可注入的本機憑證 provider 測應用層，Windows 驗證使用隔離使用者測 DPAPI 重新開啟和跨使用者拒絕。測試網路不接公司服務。
- 測試兩個 origin 不可互換憑證、跨 origin redirect／TLS pin 變更拒絕、過期及撤銷、錯 actor／Bridge、其他成員的選取、公開 GET 與目錄 POST、詳情 413／目錄超大回應、惡意或截斷的 archive／base64、錯 digest、同版本衝突、路徑與重複鍵、未知 kind、選取與安裝間崩潰、更新競態、撤權、離線和重試去重、提交結果未明、獨立審核狀態，以及 credentials／公司資料不進 log／設定／備份。驗證 HTTP 拒絕後的本機狀態與兩位助理的授權。
- stub 亦可模擬「平台還沒有一般知識上傳／MCP／Plugin 分發」。等平台核定相應契約再加合成對照，列為不同驗收能力，避免 CI 先假設線上支援。

| 3F.6 客製 MCP、後續 Plugin | 等公司提供成品類型／治理契約。MCP 接 3E 可執行檔及本機工具信任並驗發佈。Plugin 接 3G Registry 和權限政策，先在隔離 profile 驗安裝／更新，再接平台核准流程。 |

風險集中在部署與原始碼的契約差異、Member／Bridge 分開的網路與 TLS、平台類型缺口、AEP 工具語意對 OEP 的對應，以及無 idempotency 的跨端狀態。前兩個切片先取得部署能力。未知或不支援的型態保留清楚的唯讀狀態。3E／3G 安裝器共用本機驗證，3F 按確定的格式開啟入口。序列化本機操作、平台對帳及原子生效處理部分失敗。DPAPI、快取及本機日誌都以本機 profile 隔離。

### 擁有者待決與建議預設

1. **Bridge 部署與裝置准入。** 測試機的 Bridge API origin、部署版本及可登錄的 Windows 裝置是哪個？建議公司筆電優先、用專用 OEP Bridge ID 和專用成員、另一位管理者審核。兩個 origin 分別取得管理者提供的 fingerprint。如 SAN 不匹配或缺失，預設請管理者發符合名稱或 IP SAN 的憑證。
2. **MCP／Plugin 與一般知識上架合約。** 部署是否有 HEAD 未涵蓋的正式套件路由或受管上架流程？若無，建議由平台擁有者核准同一服務的新契約，提供精確版本、不可變 bytes、SHA-256、相容／權限 metadata、受眾與審核回執。先完成原有 Skill／Workflow 路由與已發布知識安裝，MCP、Plugin 及一般知識發布的遠端入口依契約啟用。
3. **BI 格式及資料治理。** 哪些 BI schema／證據可互轉與發布、可用讀者範圍為何？建議先驗一套合成 BI schema，成員同意的最小測試團隊。組織範圍另確認，OEP 預設關閉公開分享及同人核准。正式資料沿用擁有者核准的分類與授權。
4. **離線權利與更新頻率。** 公司是否要求已下載的能力定期重新取得存取授權？建議按本機優先保留已驗證且沒有已知撤銷的版本，目錄預設手動刷新，可選每日 metadata 檢查。若公司要求租期，先確定期限、撤銷狀態來源與逾期行為再啟用相關能力。
