# Phase 3F 摘要

- OEP 的「能力」會連到擁有者的測試機上的 Shared Capability Marketplace。
- 日常用擁有者自己的帳號。跨機驗收用專用成員帳號與另一位審核者。
- OEP 會先核對平台的憑證指紋。Windows 保護登入憑證，密碼只在登入時使用。
- 實際探測確認平台首頁和健康檢查可用。已登入的功能留待專用帳號驗證。
- 「能力」左欄切換功能，中央搜尋和篩選，右欄看版本、來源、權限與可用操作。
- 選定版本、驗證檔案並安裝後，再由擁有者指定哪些助理可使用。更新預設手動確認。
- 已發布的知識庫可獨立安裝與引用。建立知識庫的 Plugin 可另行安裝。
- AEP 已有 Skill、Workflow 的送審流程，以及一般知識成品的下載方式。
- 一般套件的下載需要平台的 Bridge API。MCP 執行檔、一般知識上架和 OEP Plugin 仍需確認平台契約。
- 斷線時可繼續使用已核准且符合平台政策的本機版本。OEP 會標示上次同步時間。
- 後續用合成套件在兩台機器驗收。CI 使用本機測試服務。公司內容與登入資料留在獲准環境。

建議順序為連線登入、目錄更新、Skill／Workflow 安裝、送審、知識庫、MCP 與後續 Plugin。

請擁有者確認 Bridge 的位置、公司裝置資格與憑證、尚缺的套件與上架接口、BI 分享範圍，以及離線使用期限。
